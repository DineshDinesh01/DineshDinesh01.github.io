    What changed: the quality of the output depended as much on the data and document structure as on the model.

    Platform modules and a general-purpose IDP with handwriting, faces and QR codes. Jul–Dec: deployed on an NBFC client’s team to build co-lending platform modules that went to production.

    What changed: production software brings problems beyond feature logic: large uploads, encryption and access control on real client data.

    IDP release 3.0co-lending platform
  3. 2024

    Software Engineer · AI integrations

    SaaS-partner integrations, voice-agent POCs, a first LLM fine-tune, model serving on Triton and Kubernetes, and the start of the US health-insurer work.

    What changed: not every problem needs an LLM. Deterministic lookups and API operations belong in code.

    partner invoicesvoice agentGPU serving
  4. 2025

    Senior Software Engineer · promoted Apr 2025

    Production readiness for a prior-auth platform, health-insurer phases, regulatory-filing, drawing and timesheet POCs. Jun–Dec: a multi-agent bid-pricing system for a global market-research company, delivered to production.

    What changed: an agent can produce valid-looking output and still be wrong. Evaluation must check the answer, not just its format.

    prior-auth platformprior-auth faxesbid-pricing agents

Principles

Three rules I work by.

R/01

Get the data right first.

A model can’t reason over a page that was never stored.

large-document architecture
R/02

Decide what is true in one place.

A value is decided once, after validation. Formatting never changes it.

large-document architecture
R/03

Agents for judgement. Code for certainty.

Arithmetic, hard rules and lookups belong in code. Evaluations check that the answers are right.
